# Building and releasing (maintainer notes)

## Build

The engine files, `Books/*.lua`, `Assets/Parchments`, `Assets/Seal*.tga` and `BoarsBook.toc` are generated by the
Lore Book build tool from `addon.json`, `book/` and `art/seal.png`:

```
python -I tools/make_book_addon.py <path>/boars-book
```

It copies the engine files listed in Lore Book's `editions/book/files.txt` and checks every book with the addon's own
validator (limits, required fields, unique ids). It also checks that every achievement points to a heading present in
every translation. Then it writes the generated files.

## Release

1. Raise `version` in `addon.json`, add the version to `CHANGELOG.md`, rebuild.
2. A new edition of the text: raise `revision` in `book/*.json`. Readers keep their place.
3. Commit, tag and push: `git tag v1.0.1 && git push origin main --tags`.

The `Release` workflow (`.github/workflows/release.yml`, BigWigsMods/packager) builds `BoarsBook-<tag>.zip` without
the files listed under `ignore` in `.pkgmeta`. It publishes the zip as a GitHub release with the changelog, and on
CurseForge once the TOC carries `X-Curse-Project-ID` and the repository has the `CF_API_KEY` secret.
